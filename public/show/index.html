Blue Boy Adventure

这是一个浏览器端像素风 2D 动作冒险游戏，核心目标不是单纯“能通关”， 而是做成一个可以探索、可以选关、可以编辑、可以持续扩展的完整小游戏。

  • 浏览器点击即玩，不需要安装客户端。
  • 主线关卡、世界地图、商店、Boss、结算页全部分场景组织。
  • 地图和节点尽量数据驱动，方便以后继续加关卡或做社区分享。
项目类型 课程作业 / Web 游戏
技术路线 Phaser + Vite + JavaScript
展示重点 玩法 + 技术实现 + 可扩展性

需求分析

这个项目最初不是只做“打通一关就结束”的演示，而是希望它像一个完整的小型游戏： 有起点、有探索、有选关、有商店、有 Boss、有结局，也保留后续扩展空间。

不只是通关 玩家可以在世界地图上自由移动，选择不同节点进入关卡。
支持探索和回访 章节解锁、宝物收集、商店返回、关卡重进，都能靠存档状态维持。
配套编辑器 关卡编辑器和世界地图编辑器是独立网页工具，便于自己继续扩展地图。
未来社区化设想 如果后面开放分享，还可以上传自制关卡、交换地图、交流玩法。

技术选型

JavaScript + Phaser JavaScript 负责规则、状态和数据流，Phaser 负责 2D 场景、精灵、碰撞、输入和物理；我把核心玩法建立在这套框架上，而不是从零写底层图形接口。
Vite 开发启动快、热更新快，适合这种需要频繁调关卡和素材的课程项目。
浏览器部署 打包后可以直接放到 GitHub Pages，老师和同学点链接就能玩。
本地存档 用 localStorage 保存进度、背包、装备和音量，不依赖后端也能完整体验。

实现思路

1. 场景拆分 标题页、世界地图、主关卡、商店、结算页各自独立，进入和返回都通过场景切换完成。
2. 数据驱动 地图、节点、商店、章节、任务目标都放在数据文件里，代码只负责读取和执行规则。
3. 战斗系统 角色支持近战、远程、格挡、完美格挡、升级、法力恢复，敌人支持追踪、前摇、击退和死亡动画。
4. 关卡逻辑 章节完成后能解锁下一个节点；Boss 关有切镜头、战前宣言、战斗状态切换、战利品发放和 credits。
5. 编辑器工具 关卡编辑器用于铺 tile 和摆实体；世界地图编辑器用于拖节点、连路径、导入导出 JSON。

更完整的成长线 继续补装备、技能、怪物 AI、支线任务和成就系统。

引擎实现

这一版可以理解成我在 Phaser 上面再做了一层轻量运行框架：输入先变成状态，逻辑在 `update()` 里统一结算，场景、资源、音频和存档都分开管理。这样答辩时如果老师问“你这个引擎是怎么工作的”，你就可以从下面这几块讲。

主循环 游戏每帧都会进入 `update(time, delta)`。我不是直接在按键事件里改游戏结果，而是先把输入记录下来，再在每帧里统一消费，这样逻辑不会散到各处。
场景系统 标题页、世界地图、主关卡、商店和结算页都拆成独立 Scene。 场景切换时只传必要的数据，比如章节编号、返回节点、出生点和存档状态。
输入层 键盘事件先变成 `pendingAttack / pendingPause / pendingInteract` 这类标志位，再在 `update()` 里统一处理。 这样暂停、对话、菜单和战斗不会抢同一个按键。
资源加载层 图片、音效和地图文本都在 `preload()` 里统一加载，并且通过 `publicPath()` 适配本地和 GitHub Pages。 场景切换时资源 key 可以直接复用，不需要重复读图。
渲染层 我打开了 `pixelArt` 和 `roundPixels`，关闭抗锯齿，让像素素材保持清晰。 HUD 固定在屏幕上，相机则跟着玩家走，所以世界和界面是分层渲染的。
碰撞与物理 角色、怪物、门、岩石、掉落物都用独立碰撞盒处理。 tile、实体和交互点是分开的，判断依据是矩形碰撞，不是“看起来碰上了就算”。
状态机 角色有移动、攻击、格挡、受击、击退、死亡和睡觉等状态，Boss 也有待机、cutscene、战斗和掉宝状态。 这些状态互相排斥，保证同一时刻只有一种主要行为。
AI 和寻路 普通怪物会先判断距离，再决定追击还是攻击。 追击时用网格 A*，并限制搜索范围，避免大地图里寻路过度耗时。
存档系统 进度和角色状态都保存到本地存储里，背包、装备、章节解锁、Boss 是否击败都能恢复。 这样刷新页面或者重新进入关卡时，游戏状态还能接上。
音频和光照 BGM 和音效由统一管理器控制，音量也能单独保存。 光照层负责昼夜和永夜效果，把表现层和玩法层拆开后，后续改风格会更方便。

代码结构拆解

这个项目的代码不是“一个大文件写到底”，而是按照职责切开。答辩时如果老师问你 “你怎么保证后面还能继续扩展”，就可以直接从这些文件说起。

src/main.js 创建 Phaser.Game，统一配置像素渲染、缩放策略、物理系统和场景顺序。
TitleScene / WorldMapScene 负责入口和选关。标题页只做菜单，世界地图只做节点与路径，不混合战斗逻辑。
GameScene 主玩法中心，包含地图加载、实体生成、输入处理、战斗循环、Boss 逻辑和关卡结算。
LegacyMapParser.js 把 txt 地图解析成 tile 矩阵和实体列表，使编辑器导出的文本可以直接进入游戏。
progress.js / playerState.js 前者管章节解锁和世界进度，后者管背包、装备、血量、法力和角色成长。
Inventory.js 背包按 slot 管理，装备不会因为同名而串位，卖东西和换装都依赖 slotId。
AudioManager.js / Lighting.js 统一管理 BGM、音效和音量；光照层负责昼夜、永夜和玩家周围的视野范围。
util/level-editor / util/world-map-editor 关卡编辑器和世界地图编辑器都是独立网页工具，导出结果可以被主游戏直接读取。

引擎与性能

这个项目不是直接依赖一个现成的游戏编辑器，而是自己把“输入监听 -> 状态更新 -> 场景刷新” 这一套流程串起来，做成了一个轻量的 2D 游戏运行框架。答辩时可以说这是一个“小型手搓引擎”的思路。

输入监听 角色移动、攻击、交互、确认、暂停都由键盘事件触发，再转换成当前场景里的状态标志， 最后统一在每帧更新时处理，避免一个按键直接把逻辑散落到各处。
渲染策略 使用 Phaser 的场景和精灵管理方式，配合像素模式、关闭抗锯齿、整数像素对齐， 让像素风素材保持清晰，同时减少不必要的画面平滑开销。
资源复用 素材在 preload 阶段统一加载，场景切换后复用同一套资源 key。 这样避免重复读图，也减少了运行时重新创建素材的成本。
局部更新 HUD、背包、世界地图、商店、Boss 血条都按需刷新，不会整张地图重新渲染。 主循环里只更新当前激活场景所需的状态，结构更轻。
网格化寻路 怪物 AI 用的是基于格子的 A*，并且设置了搜索范围上限。 这样既能保证追踪效果，又不会让寻路在大地图上无限耗时。
数据驱动降低耦合 地图、关卡、商店、世界节点都走配置，不把大量逻辑写死在主循环里。 这让后续增加内容时，不需要反复重构核心代码。

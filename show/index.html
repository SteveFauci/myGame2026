Blue Boy Adventure

这是一个浏览器端像素风 2D 动作冒险游戏，核心目标不是单纯“能通关”， 而是做成一个可以探索、可以选关、可以编辑、可以持续扩展的完整小游戏。

  • 浏览器点击即玩，不需要安装客户端。
  • 主线关卡、世界地图、商店、Boss、结算页全部分场景组织。
  • 地图和节点尽量数据驱动，方便以后继续加关卡或做社区分享。
项目类型 课程作业 / Web 游戏
技术路线 Phaser + Vite + JavaScript
展示重点 玩法 + 技术实现 + 可扩展性

需求分析

这个项目最初不是只做“打通一关就结束”的演示，而是希望它像一个完整的小型游戏： 有起点、有探索、有选关、有商店、有 Boss、有结局，也保留后续扩展空间。

不只是通关 玩家可以在世界地图上自由移动，选择不同节点进入关卡。
支持探索和回访 章节解锁、宝物收集、商店返回、关卡重进，都能靠存档状态维持。
配套编辑器 关卡编辑器和世界地图编辑器是独立网页工具，便于自己继续扩展地图。
未来社区化设想 如果后面开放分享，还可以上传自制关卡、交换地图、交流玩法。

技术选型

JavaScript + Phaser Phaser 负责 2D 场景、精灵、碰撞、输入和物理，适合像素风网页游戏。
Vite 开发启动快、热更新快，适合这种需要频繁调关卡和素材的课程项目。
浏览器部署 打包后可以直接放到 GitHub Pages，老师和同学点链接就能玩。
本地存档 用 localStorage 保存进度、背包、装备和音量，不依赖后端也能完整体验。

实现思路

1. 场景拆分 标题页、世界地图、主关卡、商店、结算页各自独立，进入和返回都通过场景切换完成。
2. 数据驱动 地图、节点、商店、章节、任务目标都放在数据文件里，代码只负责读取和执行规则。
3. 战斗系统 角色支持近战、远程、格挡、完美格挡、升级、法力恢复，敌人支持追踪、前摇、击退和死亡动画。
4. 关卡逻辑 章节完成后能解锁下一个节点；Boss 关有切镜头、战前宣言、战斗状态切换、战利品发放和 credits。
5. 编辑器工具 关卡编辑器用于铺 tile 和摆实体；世界地图编辑器用于拖节点、连路径、导入导出 JSON。

关键技术细节

场景生命周期 每个玩法模块都用 Phaser Scene 拆开。标题页负责入口，WorldMapScene 负责选关， GameScene 负责主玩法，ShopScene 负责买卖，CreditsScene 负责结算和回放。 场景之间通过 `scene.start / pause / resume / launch` 传递状态。
地图读取 关卡地图从 txt 里读取，前半段是 tile 矩阵，`#Entity` 后面是实体列表。 这样地图数据和游戏逻辑分离，编辑器导出的文本可以直接被主游戏加载。
碰撞和交互 地图 tile、门、岩石、掉落物、NPC 都有各自的碰撞/交互属性。 角色移动时会先做边界和碰撞检测，再决定是否能推箱、拾取、对话或开门。
战斗判定 近战攻击不是“按键立刻结算”，而是有前摇、命中帧和收招。 格挡会检查敌人的攻击方向和时间窗，完美格挡会触发反击收益，怪物也会进入失衡状态。
怪物 AI 普通怪物先判断距离，再切换追踪或攻击；追踪时使用网格 A* 寻路。 Boss 则额外维护切镜头、战前宣言、战斗阶段、血条显示和胜利掉落。
存档与扩展 进度、背包、装备和音量都保存在本地存储里。 世界地图节点、章节配置、商店库存也都集中在数据文件，后续加关卡时只要补配置即可。

代码结构拆解

这个项目的代码不是“一个大文件写到底”，而是按照职责切开。答辩时如果老师问你 “你怎么保证后面还能继续扩展”，就可以直接从这些文件说起。

src/main.js 创建 Phaser.Game，统一配置像素渲染、缩放策略、物理系统和场景顺序。
TitleScene / WorldMapScene 负责入口和选关。标题页只做菜单，世界地图只做节点与路径，不混合战斗逻辑。
GameScene 主玩法中心，包含地图加载、实体生成、输入处理、战斗循环、Boss 逻辑和关卡结算。
LegacyMapParser.js 把 txt 地图解析成 tile 矩阵和实体列表，使编辑器导出的文本可以直接进入游戏。
progress.js / playerState.js 前者管章节解锁和世界进度，后者管背包、装备、血量、法力和角色成长。
Inventory.js 背包按 slot 管理，装备不会因为同名而串位，卖东西和换装都依赖 slotId。
AudioManager.js / Lighting.js 统一管理 BGM、音效和音量；光照层负责昼夜、永夜和玩家周围的视野范围。
util/level-editor / util/world-map-editor 关卡编辑器和世界地图编辑器都是独立网页工具，导出结果可以被主游戏直接读取。

老师可能追问什么

为什么不用后端？ 这是单机课程作业，核心目标是完整玩法和快速展示，所以把存档放在本地就足够。 这样部署更简单，点 GitHub Pages 链接即可玩，不需要额外服务器。
为什么不用 Java 继续写？ 这一版目标是网页即玩和易展示。Phaser 对 2D 精灵、碰撞和场景切换支持很好， 用浏览器技术也更方便做编辑器和在线发布。
怎么保证 Boss 关可重复挑战？ Boss 是否击败、宝物是否已获得都分成独立进度字段。 重新进入关卡时会根据进度重建 Boss、血条和掉落，而不是依赖临时运行状态。
地图和编辑器怎么对上？ 编辑器保存的是统一格式：tile + entity + 节点配置。 游戏端只读取同一套数据结构，不会出现“编辑器能看，游戏里不认”的情况。
为什么同名装备不会串？ 背包里用的是 slotId，而不是只看 itemId。 所以两个相同道具也能分别装备、分别出售，不会出现“装备一个，全体都装备”的问题。
如何做调试模式？ 在 `GameScene` 里单独维护 developerMode 标志位，把 no clip、invincible、恢复进度等功能放进暂停菜单， 这样不影响正常流程，也方便展示调试能力。
怎么部署到网页？ `vite.config.js` 里配置了 GitHub Pages 的 base 路径，推到 `main` 后由 GitHub Actions 自动构建并发布 `dist/`。
